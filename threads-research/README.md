# Threads市場調査 自動レポート（楽天アフィリエイト「つむり」用）

チームチャミの市場調査担当が、Threadsで伸びている投稿を**毎朝7時（日本時間）**に自動で下調べし、
採用条件の判定・分析・応用案づくりを支援するための仕組みです。

## これは何をするものか

毎朝 06:50 JST にクラウド上で調査セッションが自動起動し（Chromebookを閉じていても動きます）、
以下の「本日の調査シート」を生成してメール＋プッシュで通知します。

- 3ジャンル（暮らしの便利グッズ／時短家事／犬のいる暮らし・ペット用品）の直近の話題・候補投稿の下調べ
- 採用条件を判定するための**数値記入テンプレ**（表示回数・フォロワー数を貼り付ける欄）
- 候補ごとの「伸びた理由の仮説」と「つむりの投稿への応用案」のドラフト

## なぜ「半自動」なのか（重要な制約）

Threadsの**表示回数・フォロワー数の実数**は、この自動実行環境からは取得できません。
理由：

1. Threads公式API（graph.threads.net）はこの環境ではネットワーク遮断されており、かつ仕様上
   「自分のアカウントの投稿・インサイト」しか返しません（他人のバズ投稿・フォロワー数は取得不可）。
2. threads.com への直接アクセスもこの環境では遮断されています。
3. Web検索では個別投稿の表示回数・フォロワー数まで安定して取れません。

→ そのため**数値の確認だけは人が1ステップ担当**します。これは
「確認できない数値は推測しない」という運用ルールを守るための設計です。
数値が取れないものは、シート上で必ず `未確認` と表記します。

## 使い方（毎朝のながれ）

1. 朝、メール／プッシュで「本日の調査シート」を受け取る。
2. シートの候補投稿を Threads アプリ（またはログイン済みブラウザ）で開き、
   各投稿の **表示回数** と **投稿者のフォロワー数** をシートの該当欄に貼り付ける。
3. 「数値を埋めました。採用判定と仕上げをお願いします」と Claude に返信する。
4. Claude が採用条件（①表示回数>10,000 ②表示回数>フォロワー数）で自動判定し、
   拡散倍率の計算・伸びた理由分析・つむりへの応用案を仕上げる。

所要時間の目安：朝の数値貼り付けは5〜10分程度です。

## 手動で今すぐ試すには

このセッション（または新しいセッション）で次を伝えてください：
「`threads-research/daily-research-guide.md` に従って本日の調査シートを作って」

## 止めたい・変更したいとき

- 停止／再開／時刻変更：Claude に「Threadsの朝7時レポートを止めて／時刻を変えて」と伝えてください
  （内部的にはスケジュールタスクを操作します）。
- 調査ジャンルや採用条件の変更：`threads-research/criteria.md` を編集してください。

## 構成ファイル

- `criteria.md` … 調査ジャンル・採用条件・つむりのアカウント方針
- `daily-research-guide.md` … 自動セッションが毎朝たどる手順
- `report-template.md` … 出力する「本日の調査シート」のひな形
- `reports/` … 日次レポートの保存先（必要に応じて）
